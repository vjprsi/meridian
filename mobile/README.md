# Meridian mobile apps (Flutter)

| App | Path | Channel | Keycloak client | Redirect |
| --- | --- | --- | --- | --- |
| Customer banking (iOS / Android) | `customer_app/` | `/v1/me` (customer-channel-service) | `meridian-customer-mobile` | `io.meridian.customer:/oauth2redirect` |
| Agent outlet (iOS / Android) | `agent_app/` | `/v1/agent` (agent-channel-service) | `meridian-agent-mobile` | `io.meridian.agent:/oauth2redirect` |

Both: Flutter 3.47 / Dart 3.13, null-safe, Material 3 (light / dark), English and Kiswahili (`flutter gen-l10n`, ARB
files in `lib/l10n`), OIDC authorization code + PKCE through the system browser (`flutter_appauth`), secrets in the
platform keystore (`flutter_secure_storage`). The Keycloak clients are generated by `tools/keycloak_realm.py`
(`infra/local/keycloak/meridian-realm.json`).

The Flutter SDK is in `D:\DevTools\flutter` (not on PATH; see `docs/DEV_TOOLS.md`). In Git Bash:

```bash
F=/d/DevTools/flutter/bin/flutter
cd mobile/customer_app        # or mobile/agent_app
$F pub get
$F analyze                    # must report "No issues found!"
$F test                       # unit + widget tests (contract tests read ../../generated/openapi)
$F build web --dart-define-from-file=env/dev.json    # smoke build (dev auth mode; no native toolchain needed)
$F run -d chrome --dart-define-from-file=env/dev.json
```

## Configuration and environments

All settings are compile-time `--dart-define`s, grouped per environment in `env/<env>.json` and passed with
`--dart-define-from-file=env/<env>.json`:

| Key | Meaning |
| --- | --- |
| `MERIDIAN_ENV` | Label shown in the app (`local`, `dev`, `staging`, `prod`) |
| `MERIDIAN_AUTH_MODE` | `oidc` (Keycloak) or `dev` (dev security mode headers; default on web) |
| `MERIDIAN_API_BASE_URL` | Edge gateway (`/v1/...` appended) |
| `MERIDIAN_OIDC_ISSUER` / `MERIDIAN_OIDC_CLIENT_ID` / `MERIDIAN_OIDC_REDIRECT` | Identity provider |

`env/local.json` targets the local stack from the Android emulator (`10.0.2.2` = the host). `staging` / `prod` files
are created by the release pipeline (not committed); production builds must use `https` issuers and APIs (plain `http`
is accepted only because AppAuth is told `allowInsecureConnections` for `http://` issuers).

## Native builds (out of scope on this machine; steps)

Android:

1. Install the Android command-line tools (or Android Studio), then `sdkmanager "platform-tools" "platforms;android-36"
   "build-tools;36.0.0" "system-images;android-36;google_apis;x86_64"`; `flutter config --android-sdk <sdk>`;
   `flutter doctor --android-licenses`.
2. `flutter run -d emulator-5554 --dart-define-from-file=env/local.json` (debug; the local stack is plain http, so a
   debug-only `network_security_config` allowing cleartext to `10.0.2.2` is needed for local runs).
3. Release: create an upload keystore outside the repo, add `android/key.properties` (git-ignored) and a
   `signingConfigs.release` reading it in `android/app/build.gradle.kts`; use Play App Signing.
   `flutter build appbundle --release --obfuscate --split-debug-info=build/symbols --dart-define-from-file=env/prod.json`.
4. Flavors per environment (optional, when several builds must coexist on one device): add `productFlavors`
   (`dev`, `staging`, `prod`) with `applicationIdSuffix` and matching Keycloak redirect schemes, and Xcode schemes of
   the same names; build with `--flavor <env> --dart-define-from-file=env/<env>.json`.

iOS (macOS with Xcode 26+):

1. `cd ios && open Runner.xcworkspace`; set the team and bundle id (`io.meridian.customer` / `io.meridian.agent`),
   enable Keychain Sharing only if needed (not required).
2. `flutter build ipa --release --obfuscate --split-debug-info=build/symbols --dart-define-from-file=env/prod.json`,
   then upload with Transporter / `xcrun altool`. Distribution certificates and provisioning profiles stay in the
   CI keychain, never in the repo.

Not compiled here: the native code added to the generated projects (agent app `MainActivity.kt` / `AppDelegate.swift`
device-key channel; customer app `FlutterFragmentActivity` for biometrics) has not been built for lack of the Android
SDK and Xcode.
